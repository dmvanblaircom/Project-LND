/* The canonical registry of programs this Suite knows about.

   One list, and only one. A program appears here whether or not the Suite can
   render it yet; what makes it selectable is that it names a `config`, and the
   config file existing is what makes that true. There is deliberately no
   second "available teams" list to drift out of step - availability is derived
   (docs/decisions/0014-one-registry.md).

     teams/index.js  ->  TEAM_REGISTRY  ->  TeamOS.registry  ->  the chooser
                                                              ->  the boot script
                                                              ->  the worker

   Fields:

     id          the Suite's own id for the program. Lower case, digits and
                 hyphens only - it becomes a file name and a ?team= value, and
                 the boot script refuses anything else.
     name        how the program is written out.
     short       how it is written where space is tight.
     conference  for grouping in the chooser. A program with none says
                 "Independent".
     abbr, nick  the provider's short code and nickname, which people search
                 by. The nickname is also shown under the program's name.
     providerId  the data provider's id for the program, so TeamOS can ask
                 for its mark (logo). Optional.
     config      teams/<id>.js, when one exists. ABSENT means the program is
                 known but not yet selectable, which is a real state: it is
                 what the chooser greys out rather than hiding.

   GENERATED by tools/build-registry.js from ESPN's standings page, weekly,
   by the Action. Do not hand-edit the roster or the conferences: the next run
   overwrites them. `name` IS preserved across runs, for the case where the
   product calls a program something the provider does not. `providerId` is
   also filled in by tools/registry-ids.js from ESPN's weekly scoreboards, so
   marks do not depend on the standings page being reachable.

   Making a program selectable is writing teams/<id>.js. The generator reads
   the filesystem and fills `config` in for you; nothing declares availability.

   The roster is a UNION across runs, so a bad parse can never remove a
   program, and the generator refuses to shrink it or to emit a list too short
   to be FBS. tools/registrycheck.js keeps it honest either way. */
